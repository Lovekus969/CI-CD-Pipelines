CI/CD is a software development practice where code changes are automatically integrated, tested, and deployed. Continuous Integration (CI) focuses on automatically building and testing code whenever changes are committed, while Continuous Delivery/Deployment (CD) automates the release process, enabling faster and more reliable software delivery.

An extension of Continuous Delivery where every successful change is automatically deployed to production without manual approval.

Goal: Deliver features to users as quickly as possible.
2. Continuous Delivery (CD)

Build ✓
Tests ✓

The application is automatically prepared for deployment.

3. Continuous Deployment

This goes one step further.

When tests pass:

Code Push
   ↓
Build
   ↓
Tests
   ↓
Deploy Automatically
   ↓
Production

No manual approval required.

Example:

You update a website.
Push to GitHub.
5 minutes later the live website is updated automatically.
Real-World Example at a Bank

Suppose you're working at a bank like TD Bank.

You fix a bug in the mobile app.

Step 1: Push Code
      git push
Step 2: CI Pipeline

      Pipeline automatically:
      
      Compile Java Code
      Run JUnit Tests
      Security Scan
Code Quality Scan
Step 3: CD Pipeline
      Create Docker Image
      Upload to Cloud
      Deploy to Test Environment
Step 4: Production
      Deploy to Customers
